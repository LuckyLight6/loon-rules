# Loon 分流规则

海外 AI 可以共用一个稳定出口；Apple 的账户登录、下载和海外媒体可以分别选路。订阅同一个 `.lsr` 地址，几台设备就能更新同一份规则。**规则只管哪些请求归到哪一组，节点和策略由你在 Loon 里选。**

## 订阅一份规则

1. 从[编号清单](INDEX.md)打开所需的规则文件。在 GitHub 点 **Raw**，复制地址。
2. 在 Loon 添加规则订阅，粘贴地址，选一个已经存在的策略。例如，把 `060-ai-overseas-all` 交给手选节点的海外 AI 策略。
3. 切到分流模式，打开目标服务。在请求记录里看**匹配规则**和**实际节点**。有多个订阅时，把专项放在通用规则前。

也可以在配置的 `[Remote Rule]` 段添加同样的订阅。下面的 `PROXY` 可以换成你的策略组：

```ini
[Remote Rule]
https://raw.githubusercontent.com/LuckyLight6/loon-rules/main/rules/060-ai-overseas-all.lsr, policy=PROXY, tag=060-ai-overseas-all, enabled=true
```

建议使用 Loon **build 1008 或更新版本**。App Store 和 Find My 的数字分片要用这个版本起支持的 `DOMAIN-WILDCARD`。[订阅语法](https://nsloon.app/docs/Rule/sub_rule/) · [规则优先级](https://nsloon.app/docs/Rule/#匹配优先级)

## 想分开选节点，还是统一出口？

| 要分流的服务 | 怎么选 |
|---|---|
| Apple | 细分选 `031–059`：账户和购买可共用一个手选节点，下载、推送和 iCloud 独立；在中国大陆，TV、News 和 Apple Intelligence 走可用代理。想统一代理再选 `030-apple-all`，不要把这份合集整体设为直连。 |
| AI | Claude、ChatGPT、Gemini、Grok 分别用 `061–064`。若海外 AI 全用同一个出口，选 `060-ai-overseas-all` 替代它的成员。国产 AI 国内入口用 `084`，国际入口用 `085`；Apple Intelligence 始终用 `046`。 |
| Google 和 Microsoft | Google 的登录、邮件、会议、网盘和下载在 `160–169`；Microsoft 的对应服务在 `100–115`。统一出口分别用 `160` 或 `100` 替代成员。Google Gemini、YouTube、Microsoft Copilot 和 GitHub Copilot 仍各自分流。 |
| 其他日常服务 | 网络接入、隐私、社交、代码托管、影视游戏、国内购物和地区兜底，按[编号清单](INDEX.md)选。相同用途的备选表只用一份。 |

**同一用途不要同时开细分表和它的合集。** Loon 的本地与插件规则可以先于订阅命中；已有宽泛规则时，光调整订阅顺序不够。域名未命中才进入 IP 阶段。仓库只在确实按已知 IP 匹配时加 `no-resolve`；私网识别和地区兜底仍保留必要的解析。

## 通用分流和广告拦截怎么选

- 通用部分选三份：`180` 补其他海外影音，`185` 补海外网站和 GFW 域名，`192` 识别国内服务。它们放在各服务专项之后。
- 国内域名和地址要用同一个策略，就选 `192`。想分开管理时，用 `194` 域名、`200` 网段、`204` GeoIP 替代 `192`。只需要按已知域名分流时，单选 `194`。
- 用 `014` 给查当前出口的 IP 检测站选代理，放在国内域名表之前。检测页显示的是打开**这个页面**时用的出口，不代表其他连接或 DNS、WebRTC 也走了同一路。若 DDNS 更新程序也用这些主机查家庭公网地址，别让那个程序经过这条代理，否则可能把域名更新成节点的 IP。
- 日常拦广告用 `023`。扩展表 `025` 默认不启用；它会额外拦部分网站统计，遇到功能异常时先关闭它，再看是哪条规则命中。

目录里的兼容表不默认叠加。需要按客户端或替代地址表分流时，再看[备选规则怎么选](COVERAGE.md#备选规则怎么选)。

## 规则怎么更新

[定时任务](.github/workflows/refresh.yml)安排在每天北京时间 **11:37**。从公开来源取数，在本地生成一整套订阅，检查单项和合集实际会先命中谁，全部通过才提交。任务失败时，设备仍能订阅之前的文件。

[来源检查报告](REVIEW.md)列出最近一次真正有差异的组；[编号清单](INDEX.md)写的是维护方式，两者不是一回事。

- **按来源筛选、组合生成**：例如 Apple 新增一个账户认证主机，只有官方表里的用途和域名都符合要求才归到 031。加入细分表后，030 的正文和来源一起更新。海外 AI 同理；不用再改一份合集。
- **比较上游，保留已审范围；随来源缩小拦截**：综合上游里的新域名不直接收录。023 单独订阅也要避开已核实的业务主机；上游小幅撤销或缩窄拦截时，订阅自动跟进。某次更新消失的范围超过原表条数的 5%，就保留已审范围，等待核实。
- **整域拦截交叉核对（025）**：保留上游、EasyList 或 EasyPrivacy、AdGuard DNS 三方都明确按整域拦截的条目。只针对脚本、路径或第三方资源的规则不转成全站拦截；能识别的例外优先。不同名单有共同来源，不能把它们当作独立投票。
- **地区兜底**：196 新增域名还要有国内产品专项作证。200 和 201 的新增地址同时查 APNIC 分配记录和运营商路由表；先比地址空间，再比较网段条数。少量撤回跟进上游，大幅变化保留上次结果。
- **已核清单**：适合局域网规则、已确认的服务入口等。程序从清单生成并校验正文；如果厂商另起一个域名，这类表不会自己发现它。

[最近检查结果](status.json)中的 `source-inventories` 另记上游已有、细分表尚未解释的范围。例如，一份叫“国内 AI”的上游也可能列出国际版。程序分别核对它们的归属，不把整张表套到国内出口。这里只记数量，不刊登未经确认的候选域名。

维护时改 [catalog.json](catalog.json) 里的来源和范围，不直接改生成文件。运行 `python3 -B maintain.py --refresh` 在本地生成；只想看结果用 `--check`，断网核对已有文件用 `--verify-files`。混合用途的 IP 规则只声明一次：需要按域名解析的地址保留 DNS，确认只匹配目标 IP 的才生成 `no-resolve`。[Loon 对这个参数的说明](https://nsloon.app/docs/Rule/ip_rule/#no-resolve)

文件头写明用途、范围、来源、创建时间和正文更新时间；日期使用 UTC。只改说明或重新检查不会刷新正文日期。[检查结果](status.json) · [来源与许可](NOTICE.md)

## 遇到错分或连不上

先看[各服务推荐出口](COVERAGE.md)，再用[实际测试步骤](NETWORK-VERIFICATION.md)确认。域名命中不代表 DNS 和 WebRTC 出口正确；内网、其他 VPN、节点、订阅凭据和证书都应在自己设备上配置，不放进公共规则。

如果反馈问题，提供**公开主机名、Loon 版本、命中规则、预期和实际出口**就够了。不要贴完整配置、登录链接、内网域名或带凭据的日志。
